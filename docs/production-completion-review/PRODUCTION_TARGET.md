# What production completion must prove

This review targets the complete supported product, not merely readiness for another phase. It does not broaden fiscal/ERP claims or settle unselected workload, deployment or security policy. Product version remains v0.0.1; a review package cannot unlock it.

## Different acceptance boundaries

| Boundary | What must work | What it does not complete |
|---|---|---|
| Current narrow scope | Every introduced claim has current source evidence and recurring regression; no introduced BLOCKED responsibility carried forward | Missing business/roles/profile/Web/Worker runtime is not supplied by a passing baseline |
| Backend delivery | Joined current-authority commercial/admin cases through owned APIs, selected consequences, live providers, least-privilege deployment, restore/load/release evidence | Actual browser, offline workstation or Guard behavior |
| Tenant Web | Qualified session topology and real browser business outcomes against accepted API contracts | Private Admin device/session boundary |
| Admin Web | Separate real registered-device/person authority and private operations, with independent host/failure behavior | Tenant or workstation authority |
| Backend/two-Web release | Exact integrated GATE-002/003/004/005 scope and selected branches | Later Workstation/Sync/Guard and complete-product gate |
| Complete product | All accepted required product outcomes, including selected offline/device/update/recovery/peripheral cases, operate on actual target infrastructure/hardware | Arbitrary future integrations, unselected customer variants, tax/fiscal/full-ledger or unsupported HA claims |

## Evidence before acceptance

For each material introduced claim, record the focused owner, supported case, falsifiable evidence, permanent/recurring guard, requalification trigger and non-claims. Ensure BLOCKED=none inside the exact accepted scope. Absent future responsibility stays NOT_INTRODUCED and visible; it cannot fulfill a selected product outcome.

Required evidence includes:

- Current authorization on commands and replay, negative cross-tenant/account/device cases and effective grant/revocation reconciliation.
- Immutable financial/pricing/debtor/policy facts, actual partial outcomes and race-safe remaining balances/quantities.
- Atomic mutations/receipts/consequences; cancellation/deadline distinction; response loss, process crash/restart and ambiguous provider reconciliation.
- Real PostgreSQL/OpenFGA/identity/selected-provider tests; real browser/device/TLS checks for host-bound claims.
- Normal parallel repository gate, independent host restore/build/publish and remote CI; coverage interpreted per claim, not aggregate percentage as production proof.
- Real deployment/secrets rotation/least privilege, full restore of business and authority state, measured capacity/noisy-neighbor/resource limits and failed-release recovery.
- Actual target OS/hardware for local encryption/WAL, peripherals, Guard, signed updates and rollback/recovery claims.

A target environment that is unavailable leaves named evidence pending. Writing test code is useful but not a passed test. No claim of exactly-once provider effects, OS-level isolation from Autofac/actor scopes, transparent HA or zero downtime is admitted without a separately scoped guarantee and evidence.

## Review limits

Nine static perspectives can miss defects and cannot make production acceptance. They collect actionable findings and prevent scope omissions. Execution requires task-specific authors, independent adversarial review, inspected actual runs and accountable owner acceptance. The planning package preserves completed work and assigns remaining deltas instead of rewriting working components.
