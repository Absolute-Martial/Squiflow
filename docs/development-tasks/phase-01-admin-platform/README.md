# Phase 01 — Admin and platform backend assignments

This directory schedules Admin/platform and tenant-control backend work. Current executable truth remains in [README.IMPLEMENTATION.md](../../../README.IMPLEMENTATION.md). Existing membership and incoming request-budget work require current evidence; incoming invoice core is accounted for in the baseline/commercial track. Historical totals do not qualify a different dirty source tree.

Use [shared agent rules](../AGENT_RULES.md) and [handoff/integration rules](../HANDOFF_AND_INTEGRATION.md). `Status` describes scheduling only. Decisions require accepted focused-owner updates before implementation. Conditional tasks proceed only when the stated trigger is earned; no phase label creates a role, resource, process or feature requirement.

The [generated phase index](TASK_INDEX.md) contains all **ADM-001 through ADM-034** assignments and current exact dependencies. Each full file supplies scope, decisions, failures, regressions and a copyable prompt. Dependencies from other tracks are already declared in metadata.

First complete ADM-001, then ADM-002. ADM-003 qualifies/fixes only real route/readiness/admission gaps. ADM-004 and ADM-008 close provider topology and tenant authorization policy before dependent operations. ADM-009 → ADM-010 → ADM-011 separates durable proposal, grant reconciliation and revoke/handoff so external/local ambiguity is not hidden inside a broad platform task. ADM-018 → ADM-019 → ADM-020 → ADM-021 separates catalog, typed settings, publication and activation; ADM-022 remains conditional on real graph variation.

ADM-007 → ADM-025 defines/implements local account availability. ADM-026 conditionally implements one accepted recovery operation. ADM-032 reuses the same lifecycle through tenant-authorized CoreApi team ingress for WEB-012; routine tenant administration must not require platform authority or an AdminApi proxy.

ADM-034 defines and proves backend freshness/guarded transport using the early WEB-001/UIA-001 topology contracts. ADM-011 consumes it for accepted Owner handoff; browser usage follows later. ADM-017 defines/drills application recovery, OPS-018 proves the combined infrastructure recovery set, then ADM-016 qualifies rotation/revocation. Neither recovery nor backend readiness waits for an unbuilt Web runtime.

Conditional additions are ADM-027 verified domains; ADM-028/029 one selected application key-policy/lifecycle operation; ADM-030 narrow support access; ADM-031 actual resource-scope enforcement after ADM-013; and ADM-033 a real feature release control. Select the workload and accept its contract first. [Coverage](../COVERAGE_MATRIX.md) and [orchestration](../ORCHESTRATOR.md) define omission/activation and shared-file ownership. Existing provisioning/import/membership operations are qualification inputs, not rebuild tasks.
