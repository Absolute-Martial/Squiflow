# Model routing

Models below are assignment labels selected by the user, not claims about API availability or fixed pricing. Verify the available model before dispatch; do not silently substitute a cheaper model on authority or money work.

| Model | Suitable bounded work | Required review / stop condition |
|---|---|---|
| GPT-6 Luna (high) | Read-only inventory, focused documentation/path cross-checks, presentation with already fixed contracts, mechanical assertions following existing patterns | Stronger review for touched authority/persistence; stop if decisions or new security semantics appear |
| An available Flash model | Same bounded mechanical/read-only work when explicitly selected | This is a capability tier, not a claimed model/API name; retain the task default until the dispatcher records an approved substitution |
| GPT-6.1 Sol | Identity and authorization, grant/revocation/reconciliation, money, durable concurrency/recovery, new host/session security, policy interpretation and release qualification | Accountable owner accepts business/security decisions and declared release claims |

Tasks carry one default `Model:` value. Luna/Flash work must name exact paths and frozen contract inputs; its output is reviewed and cannot settle policy. A small model is never assigned “finish backend,” broad security architecture, invoice/payment semantics, OpenFGA authority, financial correction or crash-safe external execution. A strong model can perform small tasks, but inexpensive bounded work should remain separated so the handoff is useful.

Topology decisions WEB-001/UIA-001 and provider/deployment choices are strong-model work even if the first artifact is documentation. A decision changes the authority/failure boundary; it is not a mechanical writing task. GATE tasks also remain strong-model tasks because inspection of tests alone cannot decide the scope of a production claim.

Re-route a mechanical task to Sol if it reveals tenant isolation changes, a persisted/wire compatibility choice, ambiguous money/rounding/numbering, actor/device authority, uncertain provider effects, transaction/concurrency/retry behavior or a new runtime dependency. Return the bounded finding and proposed scope; never hide it in a “small refactor.” Disjoint file ownership and dependency evidence matter more than model concurrency. No model may bypass canonical owners, missing environments, required static review or normal final integration qualification.
